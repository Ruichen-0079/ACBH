# ACBH v0.4 unattended durability monitoring

These monitors record one JSONL sample every 60 seconds. They do not contain an
access token, player address, private-key path, or player IP. A successful TCP
probe is an availability signal only; it is not counted as Minecraft client
validation.

Each monitor rotates at 20 MiB and retains at most five JSONL files. The
16-hour collection commands create summaries but do not claim that the test
passed; review all non-ONLINE and probe-failure counts first.

## Windows Host

The Windows monitor records the local Agent/component states, Java and frpc
counts, Agent resource use, public-port probe, protected 25565 listener, and
Agent log-directory size.

For the isolated validation environment, start it with:

```powershell
$script = "C:\ACBH\ACBH-v04-relay-first-clean\scripts\durability\windows-monitor.ps1"
& $script -Mode start `
  -IntervalSeconds 60 `
  -OutputDirectory "C:\ACBH\v04-durability-monitor" `
  -AgentStatusUri "http://127.0.0.1:6132/local/v1/status" `
  -PublicHost "121.40.101.224" `
  -PublicPort 25575 `
  -ProtectedPort 25565 `
  -AgentLogDirectory "C:\ACBH\v04-test-state\acbh\logs"
```

View the monitor and latest sample:

```powershell
& $script -Mode status -OutputDirectory "C:\ACBH\v04-durability-monitor"
```

Stop only the fingerprint-verified monitor process:

```powershell
& $script -Mode stop -OutputDirectory "C:\ACBH\v04-durability-monitor"
```

After 16 hours, collect the Windows summary:

```powershell
& $script -Mode collect `
  -OutputDirectory "C:\ACBH\v04-durability-monitor" `
  -SummaryPath "C:\ACBH\v04-durability-monitor\windows-summary.json"
```

## VPS

The deployed test paths are:

- monitor: `/opt/acbh-v04-test/durability/vps-monitor.sh`
- systemd unit: `acbh-v04-test-monitor.service`
- JSONL output: `/var/log/acbh-v04-test/durability/`

The VPS monitor observes the isolated Coordinator/frps systemd states,
25575/6122/7001 listeners, local 25575 probe, service resource use, process
counts, and isolated log-directory size. Agent, Minecraft, and protected local
25565 state remain authoritative in the Windows samples.

Start unattended monitoring:

```sh
systemctl start acbh-v04-test-monitor.service
```

View service status and the latest sample:

```sh
systemctl status --no-pager acbh-v04-test-monitor.service
tail -n 1 /var/log/acbh-v04-test/durability/vps-monitor-*.jsonl
```

Stop only the isolated monitor service:

```sh
systemctl stop acbh-v04-test-monitor.service
```

After 16 hours, collect the VPS summary:

```sh
/opt/acbh-v04-test/durability/vps-monitor.sh collect
cat /var/log/acbh-v04-test/durability/vps-summary.json
```

## 16-hour review

Do not declare durability success merely because the monitors ran for 16
hours. Check at minimum:

- sample duration and expected sample count;
- every Agent, Minecraft, Relay, Coordinator, and frps non-healthy sample;
- all public probe failures;
- any protected-25565 listener failure or PID change;
- maximum Java/frpc counts for duplication;
- Agent and VPS resource growth;
- monitor/service restarts and missing intervals;
- the planned exact-PID frpc exit and isolated Coordinator restart events.

The accepted v0.4 durability threshold is 16 continuous hours. The isolated
run recorded in `v04-smoke-results.md` passed that threshold; it does not claim
that a 24-hour run occurred. Publish `v0.4.0-rc1` after review and merge of the
client-smoke-tested PR, then use RC feedback as the remaining input to the
final `v0.4.0` decision.
