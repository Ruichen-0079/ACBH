# v0.2 真实低配公网服务器部署 Runbook

> 面向“刚租了一台低配公网服务器，想把 ACBH 真正跑起来”的第一次实机演练。
> 本文使用已经发布的 `v0.1-demo` Pre-release 产物验证 v0.2 第一阶段目标。
> 在真实世界目录操作前，必须先做独立离线备份。

## 1. v0.2 目标

v0.1-demo 已经通过测试和本地 smoke 证明以下链路可用：

- artifact scan、validate、push、latest、pull、restore。
- Host election、generation fencing 和 takeover。
- Coordinator、Agent、Local Control 与 Dashboard 图形控制面板。
- server status/start/stop 和进程锁。

v0.2 第一阶段不急着增加大功能，而是把这些能力放到真实低配公网 VPS 上，完成一次
可重复的实机部署验证：

- Velocity A：公网入口 `25565`。
- Fabric A：本机后端 `25566`。
- Velocity B：公网备用入口 `25575`。
- Fabric B：本机后端 `25576`。
- ACBH Coordinator、Dashboard、两个 Agent / Local Control。
- Host A 推送 artifact，Host B 拉取、恢复、启动并完成接管演练。

本阶段暂不承诺自动修改 Velocity backend，也不承诺玩家无感迁移。先跑通双端口
手动/半自动接管：A 故障后，B 恢复并启动，玩家改连 `公网 IP:25575`。

## 2. 服务器购买建议

| 配置 | 建议 |
|---|---|
| 1C1G | 只适合极小测试；不要期待两个 Fabric JVM 同时稳定运行 |
| 2C2G | 推荐起步，适合小型朋友服和功能验证 |
| 2C4G | 更稳，给两个 JVM、Coordinator 和系统留出余量 |
| 磁盘 20 GB | 最低要求，只适合短期测试 |
| 磁盘 40 GB+ | 推荐，需容纳世界、模组、日志、artifact 和离线备份 |

系统推荐 Ubuntu LTS、Debian stable 或 Fedora Server。准备 Java 17；运行 Coordinator
还需要 Node.js 和 pnpm。直接使用 release 中的 Agent 二进制时不需要安装 Go。

云安全组和系统防火墙只开放：

- TCP `25565`：Velocity A。
- TCP `25575`：Velocity B。

不要开放：

- Fabric 后端 `25566/25576`。
- Local Control `6122/6123`。
- RCON。
- 裸露的 Coordinator `6121`。

Coordinator 和 Dashboard 应只绑定本机，或放在 VPN / 带 TLS 与认证的受保护网络后。

## 3. 目录规划

推荐布局：

```text
/opt/mc-stack/
├── velocity-a/
├── velocity-b/
├── fabric-a/
├── fabric-b/
├── acbh/
│   ├── coordinator/
│   ├── agent/
│   ├── config-a/
│   ├── config-b/
│   └── data/
├── logs/
└── backups/
```

原则：

- Velocity A/B、Fabric A/B 各用独立目录。
- Fabric A 与 B 绝不能同时写同一个世界目录。
- 两个 Agent 使用独立 `XDG_CONFIG_HOME`，避免 Host 身份和 token 文件互相覆盖。
- artifact storage、Coordinator state、日志和离线备份分开存放。
- `/opt/mc-stack/backups` 不是 artifact storage 的替代品；仍需定期制作离线备份。

## 4. 安装基础环境

### Ubuntu / Debian

```bash
sudo apt update
sudo apt install -y openjdk-17-jre-headless curl unzip tar
```

Node.js 与 pnpm 请使用发行版支持的 Node 20+ 安装方式，然后：

```bash
sudo corepack enable
corepack prepare pnpm@9.15.4 --activate
```

### Fedora

```bash
sudo dnf install -y java-17-openjdk-headless nodejs curl unzip tar
sudo corepack enable
corepack prepare pnpm@9.15.4 --activate
```

### 创建运行用户与目录

```bash
sudo useradd --system --create-home --shell /sbin/nologin minecraft
sudo install -d -o minecraft -g minecraft \
  /opt/mc-stack/velocity-a \
  /opt/mc-stack/velocity-b \
  /opt/mc-stack/fabric-a \
  /opt/mc-stack/fabric-b \
  /opt/mc-stack/acbh/coordinator \
  /opt/mc-stack/acbh/agent \
  /opt/mc-stack/acbh/config-a \
  /opt/mc-stack/acbh/config-b \
  /opt/mc-stack/acbh/data \
  /opt/mc-stack/logs \
  /opt/mc-stack/backups
```

### 上传、校验并解压 release bundle

在本地下载 `v0.1-demo` 的以下两个文件：

- `acbh-v0.1-demo-bundle.tar.gz`
- `SHA256SUMS`

使用 `scp`、SFTP 或云厂商文件传输上传到 VPS 的临时目录。示例中的主机名只是
placeholder：

```bash
scp acbh-v0.1-demo-bundle.tar.gz SHA256SUMS user@your-vps:/tmp/acbh-release/
```

在 VPS 上校验外层 bundle：

```bash
cd /tmp/acbh-release
grep 'acbh-v0.1-demo-bundle.tar.gz' SHA256SUMS | sha256sum -c -
```

解压后再校验 bundle 内的所有文件：

```bash
tar -xzf acbh-v0.1-demo-bundle.tar.gz
cd v0.1-demo
sha256sum -c SHA256SUMS
```

全部显示 `OK` 后安装：

```bash
sudo cp -a coordinator/. /opt/mc-stack/acbh/coordinator/
sudo install -m 0755 acbh-agent-linux-amd64 \
  /opt/mc-stack/acbh/agent/acbh-agent
sudo chown -R minecraft:minecraft /opt/mc-stack
```

ARM64 VPS 使用 `acbh-agent-linux-arm64`。不要把任何真实凭据写进上传命令或安装日志。

## 5. 部署 Velocity A/B

先下载与你的 Minecraft 版本兼容的 Velocity jar，分别放入：

- `/opt/mc-stack/velocity-a/velocity.jar`
- `/opt/mc-stack/velocity-b/velocity.jar`

仓库模板：

- [Velocity A](../../examples/single-vps-dual-stack/velocity-a.toml.example)
- [Velocity B](../../examples/single-vps-dual-stack/velocity-b.toml.example)

关键配置：

```toml
# Velocity A
bind = "0.0.0.0:25565"

[servers]
main = "127.0.0.1:25566"
try = ["main"]
```

```toml
# Velocity B
bind = "0.0.0.0:25575"

[servers]
main = "127.0.0.1:25576"
try = ["main"]
```

模板只是最小片段。真实部署还要按 Velocity 官方文档配置 modern forwarding、
player-info forwarding 和对应 Fabric 代理模组。forwarding secret 必须单独生成并保护，
不能提交到仓库。

测试启动：

```bash
sudo -u minecraft sh -c \
  'cd /opt/mc-stack/velocity-a && exec java -Xms256M -Xmx512M -jar velocity.jar'

sudo -u minecraft sh -c \
  'cd /opt/mc-stack/velocity-b && exec java -Xms256M -Xmx512M -jar velocity.jar'
```

长期运行建议使用仓库中的 systemd 模板：
`examples/single-vps-dual-stack/systemd/velocity-*.service.example`。

## 6. 部署 Fabric A/B

把同一套经过验证的 Fabric loader、启动 jar、mods、config、libraries 和必要资源分别
复制到 `/opt/mc-stack/fabric-a` 与 `/opt/mc-stack/fabric-b`。两个目录应保持：

- Fabric、Minecraft 和 modpack 版本一致。
- `mods/`、`config/` 和启动 jar 一致。
- 世界目录独立；B 的世界由 ACBH restore 更新。
- 不复制正在运行中的半写入世界。先停服或通过 RCON `save-all flush` 生成安全快照。

使用模板：

- [Fabric A server.properties](../../examples/single-vps-dual-stack/fabric-a-server.properties.example)
- [Fabric B server.properties](../../examples/single-vps-dual-stack/fabric-b-server.properties.example)

关键值：

```properties
# Fabric A
server-ip=127.0.0.1
server-port=25566
enable-rcon=true
rcon.port=25567
rcon.password=CHANGE_ME
```

```properties
# Fabric B
server-ip=127.0.0.1
server-port=25576
enable-rcon=true
rcon.port=25577
rcon.password=CHANGE_ME
```

`CHANGE_ME` 必须替换为真实强密码。不要把真实 RCON password 写入仓库、命令行或
systemd unit。可以放入权限为 `0600` 的 EnvironmentFile，再让维护脚本读取。

首次启动前：

```bash
printf 'eula=true\n' | sudo -u minecraft tee /opt/mc-stack/fabric-a/eula.txt >/dev/null
printf 'eula=true\n' | sudo -u minecraft tee /opt/mc-stack/fabric-b/eula.txt >/dev/null
```

只有在你确实接受 Minecraft EULA 后才能这样设置。

测试启动命令：

```bash
sudo -u minecraft sh -c \
  'cd /opt/mc-stack/fabric-a && exec java -Xms1G -Xmx2G -jar fabric-server-launch.jar nogui'

sudo -u minecraft sh -c \
  'cd /opt/mc-stack/fabric-b && exec java -Xms1G -Xmx2G -jar fabric-server-launch.jar nogui'
```

低内存 VPS 不应盲目给两个 JVM 都分配 2 GB。先根据总内存缩小 `-Xmx`，并考虑平时只
运行 Fabric A、接管时停 A 再启动 B。

`online-mode` 与 forwarding 必须按 Velocity + FabricProxy-Lite 或你选择的代理方案
正确配置。不要把离线模式 Fabric 裸露公网，也不要开放 `25566/25576`。

## 7. 部署 ACBH Coordinator

release bundle 的 `coordinator/` 包含编译后的 JavaScript 和 `package.json`：

```bash
cd /opt/mc-stack/acbh/coordinator
sudo -u minecraft pnpm install --prod
```

创建数据目录：

```bash
sudo install -d -o minecraft -g minecraft \
  /opt/mc-stack/acbh/data/storage
```

只绑定本机启动：

```bash
sudo -u minecraft env \
  HOST=127.0.0.1 \
  PORT=6121 \
  ACBH_STORAGE_ROOT=/opt/mc-stack/acbh/data/storage \
  ACBH_COORDINATOR_STATE_PATH=/opt/mc-stack/acbh/data/coordinator-state.json \
  node /opt/mc-stack/acbh/coordinator/index.js
```

不要把 Coordinator 裸露公网。长期运行可使用
`examples/single-vps-dual-stack/systemd/acbh-coordinator.service.example`。

本机检查：

```bash
curl --connect-timeout 3 --max-time 10 http://127.0.0.1:6121/health
```

从管理电脑建立 SSH tunnel：

```bash
ssh -L 6121:127.0.0.1:6121 user@your-vps
```

然后在本地浏览器访问：

[http://127.0.0.1:6121](http://127.0.0.1:6121/)

Dashboard 的直接路径是：

[http://127.0.0.1:6121/dashboard](http://127.0.0.1:6121/dashboard)

不要为了省去 SSH tunnel 而把 `HOST` 改成 `0.0.0.0`。

## 8. 部署 Agent / Local Control

- Agent A 对应 `/opt/mc-stack/fabric-a`。
- Agent B 对应 `/opt/mc-stack/fabric-b`。
- Agent A 使用 `/opt/mc-stack/acbh/config-a`。
- Agent B 使用 `/opt/mc-stack/acbh/config-b`。
- Local Control 只监听 loopback。

参考配置：

- [Agent A example](../../examples/single-vps-dual-stack/acbh-agent-a.example.json)
- [Agent B example](../../examples/single-vps-dual-stack/acbh-agent-b.example.json)

示例里的 `example-access-key`、`example-host-token` 和
`example-local-control-token` 都是 placeholder，不可用于真实部署。真实配置由
`acbh-agent login` 写入；Local Control token 由 Agent 自动生成并保存到对应配置目录的
`acbh/control-token`。

注册 Host A 时，通过隐藏输入和环境变量提供 access key，不把值放入 argv：

```bash
sudo -u minecraft -H sh
export XDG_CONFIG_HOME=/opt/mc-stack/acbh/config-a
read -rsp "Group access key: " ACBH_ACCESS_KEY
echo
export ACBH_ACCESS_KEY
/opt/mc-stack/acbh/agent/acbh-agent login \
  --coordinator http://127.0.0.1:6121 \
  --group-id example-group \
  --name "Public Fabric A" \
  --device-name vps-fabric-a \
  --platform linux
unset ACBH_ACCESS_KEY
exit
```

Host B 使用 `config-b` 重复流程。`example-group` 必须换成 Dashboard 创建 group 后显示
的实际 group ID。

启动两个 Local Control：

```bash
sudo -u minecraft env XDG_CONFIG_HOME=/opt/mc-stack/acbh/config-a \
  /opt/mc-stack/acbh/agent/acbh-agent control serve \
  --listen 127.0.0.1:6122

sudo -u minecraft env XDG_CONFIG_HOME=/opt/mc-stack/acbh/config-b \
  /opt/mc-stack/acbh/agent/acbh-agent control serve \
  --listen 127.0.0.1:6123
```

不要使用 `--token` 传真实 token。远程 Dashboard 还需在 SSH 命令中转发 `6122/6123`：

```bash
ssh -L 6121:127.0.0.1:6121 \
    -L 6122:127.0.0.1:6122 \
    -L 6123:127.0.0.1:6123 \
    user@your-vps
```

## 9. 首次同步流程

### Dashboard 流程

1. 打开 Dashboard。
2. 确认 Coordinator health 正常。
3. 创建或选择 group。
4. 注册 Host A，确认 Host ID。
5. 连接 Host A Local Control：`http://127.0.0.1:6122`。
6. 服务端目录填写 `/opt/mc-stack/fabric-a`，执行 **doctor**。
7. 执行 **scan**；真实世界快照优先使用 **safe-sync world**。
8. 执行 **manifest validate**。
9. 执行 **artifact push**。
10. 在 Artifacts 区检查 **latest artifact**。

Dashboard 中的 secret 只应保存在页面内存，刷新后重新输入。401/403 后重新读取对应
Host 的 token 文件，不要把 token 写入 URL、console 或浏览器存储。

### CLI 兜底流程

具体参数以 `acbh-agent --help` 与子命令 `--help` 为准。当前可用命令包括：

```bash
export XDG_CONFIG_HOME=/opt/mc-stack/acbh/config-a
/opt/mc-stack/acbh/agent/acbh-agent doctor
/opt/mc-stack/acbh/agent/acbh-agent scan --help
/opt/mc-stack/acbh/agent/acbh-agent safe-sync --help
/opt/mc-stack/acbh/agent/acbh-agent manifest validate --help
/opt/mc-stack/acbh/agent/acbh-agent push --help
```

真实世界同步优先使用 `safe-sync`，并通过受保护的 `ACBH_RCON_PASSWORD` 环境变量输入
RCON password，避免 `--rcon-password` 暴露在进程参数中。

## 10. 备用服恢复流程

Dashboard 操作：

1. 切换到 Host B / `fabric-b`。
2. 连接 Host B Local Control：`http://127.0.0.1:6123`。
3. 确认 Fabric B 已停止。
4. 执行 **pull latest artifact**，目标目录为 `/opt/mc-stack/fabric-b`。
5. 核对 manifest 和目标路径后执行 restore；不要未经确认启用删除。
6. 执行 **server status**。
7. 填写真实启动 jar 和结构化 JVM/server 参数，执行 **server start**。
8. 再次执行 **server status**，检查日志。
9. 玩家连接 `公网 IP:25575` 验证。

CLI 兜底：

```bash
export XDG_CONFIG_HOME=/opt/mc-stack/acbh/config-b
/opt/mc-stack/acbh/agent/acbh-agent server status
/opt/mc-stack/acbh/agent/acbh-agent server stop
/opt/mc-stack/acbh/agent/acbh-agent pull \
  --artifact-kind world-snapshot \
  --artifact-id latest \
  --output-dir /opt/mc-stack/fabric-b
/opt/mc-stack/acbh/agent/acbh-agent server start
/opt/mc-stack/acbh/agent/acbh-agent server status
```

`server start` 默认可读取 Agent 配置中的 server command；若配置尚未完成，以
`acbh-agent server start --help` 为准。

## 11. 故障接管演练

演练前先做好离线备份，并确保 A/B 不会同时写同一份世界数据。

1. 停止 Fabric A，或在受控测试中停止 Host A heartbeat/daemon。
2. 在 Dashboard 查看 Host A 状态变化。
3. 点击 **Run election**，或等待 heartbeat timeout 后点击 **Check timeout**。
4. 切换到 Host B，点击 **Poll assignment**。
5. 核对 assignment 后点击 **Accept takeover**。
6. Host B 执行 pull/restore/start。
7. 验证 Fabric B 日志与世界状态。
8. 点击 **Complete takeover**。
9. 确认 current host 和 generation 已变化。
10. 玩家改连 `公网 IP:25575`。
11. 检查关键区块、玩家数据、背包和世界时间是否符合最新安全快照。

CLI 没有 `election run` 子命令；该动作由 Dashboard 提供。CLI 可使用：

```bash
/opt/mc-stack/acbh/agent/acbh-agent election status
/opt/mc-stack/acbh/agent/acbh-agent election check-timeout
/opt/mc-stack/acbh/agent/acbh-agent takeover poll
/opt/mc-stack/acbh/agent/acbh-agent takeover accept
/opt/mc-stack/acbh/agent/acbh-agent takeover run --dry-run
/opt/mc-stack/acbh/agent/acbh-agent takeover complete
```

## 12. 图形控制面板验收点

逐项确认 Dashboard 能看到或执行：

- [ ] Coordinator 状态和 health。
- [ ] group 状态。
- [ ] Host A 与 Host B。
- [ ] current host。
- [ ] generation。
- [ ] latest artifact。
- [ ] Host A/B Local Control 连接状态。
- [ ] doctor。
- [ ] scan。
- [ ] manifest validate。
- [ ] artifact push。
- [ ] artifact pull / restore。
- [ ] server status / start / stop。
- [ ] election status / run / timeout check。
- [ ] takeover poll / accept / complete / fail。
- [ ] event log，且敏感字段已遮蔽。

Dashboard 不会自动修改 Velocity 配置、迁移在线玩家、切换 DNS 或保证无损热迁移。

## 13. 公网连通性检查

### Linux 监听检查

```bash
ss -ltnp | grep -E '25565|25566|25575|25576|6121|6122'
```

同时运行 Host B Local Control 时，再检查 `6123`：

```bash
ss -ltnp | grep -E '6123'
```

预期：

- Velocity A/B 监听 `0.0.0.0:25565/25575`。
- Fabric A/B 监听 `127.0.0.1:25566/25576`。
- Coordinator 监听 `127.0.0.1:6121`。
- Local Control 监听 `127.0.0.1:6122/6123`。

### 外部检查

- Minecraft 客户端连接 `公网 IP:25565`。
- Minecraft 客户端连接 `公网 IP:25575`。

### 防火墙检查

```bash
# Fedora
sudo firewall-cmd --list-ports

# Ubuntu / Debian
sudo ufw status verbose
```

检查：

- 云安全组是否开放 TCP `25565/25575`。
- firewalld/ufw 是否开放相同端口。
- Velocity 是否监听公网地址。
- Fabric 是否只监听 loopback。
- Velocity backend 是否误写端口或地址。

## 14. 失败排查

### 25565 进不去

检查 Velocity A 进程、`0.0.0.0:25565` 监听、云安全组、系统防火墙和客户端版本。

### 25575 进不去

检查 Velocity B、`25575` 防火墙规则、Fabric B 是否已启动，以及 backend
`127.0.0.1:25576`。

### Velocity 启动但后端连不上

检查 Fabric 监听地址、backend 端口、Velocity forwarding 与 FabricProxy-Lite 配置。

### Fabric 启动失败

检查 Java 17、内存参数、EULA、启动 jar、模组依赖、目录权限和服务日志。低配 VPS 常见
原因是两个 JVM 的 `-Xmx` 总和超过物理内存。

### RCON 失败

检查 `enable-rcon`、独立 RCON 端口、loopback、密码来源和 Fabric 日志。不要把真实
password 放入 argv。

### Dashboard 打不开

先在 VPS 上执行 `curl http://127.0.0.1:6121/health`，再检查 SSH tunnel。不要通过把
Coordinator 裸露公网来绕过 tunnel。

### Local Control unavailable

检查 Agent 进程、对应 `XDG_CONFIG_HOME`、监听端口和 SSH 端口转发。Host A/B 不应同时
抢占 `6122`。

### token rejected

确认读取的是当前 Host 配置目录下的 `acbh/control-token`。401/403 后重新输入；不要
使用另一个 Host 的 token。

### artifact push 失败

检查 Host auth、current host、generation、manifest creatorHostId、Coordinator storage
权限和磁盘空间。fencing 失败时不要通过修改磁盘文件绕过。

### pull/restore 后世界没变

确认 artifact kind 和 ID、latest 指针、output 目录以及 Fabric B 是否在恢复期间停止。
检查 manifest 中的世界路径，并确认启动的是 `/opt/mc-stack/fabric-b`。

### server start 没启动

执行 `server status`，检查启动 jar、Java 路径、日志和 process lock。遇到 stale/unknown
state 时先确认旧进程，按 `server repair-state --help` 操作，不要直接删除 state。

### old host / generation 冲突

说明旧 Host 或旧 generation 正在尝试写入。停止旧 Host 写入，刷新 group/election
状态，完成或失败当前 takeover；不要降低 fencing 检查。

### demo-smoke 通过但真实服不通

`demo-smoke` 使用临时目录、假世界和本机随机端口，不验证真实 Velocity、Fabric、
modpack、RCON、云安全组或公网路由。按本 runbook 分层检查每个组件。

## 15. 生产风险提示

- v0.1/v0.2 阶段仍是 demo/实验，不是成熟商业高可用方案。
- 不保证大型世界、复杂模组或高并发下无损。
- 切换期间在线玩家会断线并需要改连备用端口。
- 接管前必须保证旧主停止写入，否则可能产生世界分叉或回滚。
- 定期制作与 artifact storage 独立的离线备份，并实际验证恢复。
- Coordinator、Dashboard、Local Control、RCON 和 Fabric backend 不得裸露公网。
- 使用 SSH tunnel、VPN 或受保护反代管理，不要为方便关闭认证或 fencing。
- 首次演练使用世界副本；确认流程后再操作真实世界。

## 17. server-runtime bootstrap

v0.2 MVP 推荐使用 [`server-runtime` 主机引导](server-runtime-bootstrap.md)
同步完整可运行的 Fabric `serverDir`：

```bash
# Host A
export XDG_CONFIG_HOME=/opt/mc-stack/acbh/config-a
acbh-agent bootstrap create-group \
  --coordinator http://127.0.0.1:6121 \
  --group "example-group" \
  --server-dir /opt/mc-stack/fabric-a \
  --artifact-class server-runtime
```

Host B 从受保护输入读取 group access key，不把值放入 argv：

```bash
export XDG_CONFIG_HOME=/opt/mc-stack/acbh/config-b
read -rsp "Group access key: " ACBH_ACCESS_KEY
echo
export ACBH_ACCESS_KEY
acbh-agent bootstrap join-group \
  --coordinator http://127.0.0.1:6121 \
  --group <group-id> \
  --server-dir /opt/mc-stack/fabric-b \
  --artifact-class server-runtime
unset ACBH_ACCESS_KEY
```

在 Dashboard 的 Artifacts 区选择 `server-runtime` 可查看 latest、generation、
文件数、总字节数和 creator host。Host B 加入后保持 standby；真正接管仍必须走
election、takeover accept、恢复/启动验证和 takeover complete。
