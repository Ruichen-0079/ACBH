# v0.4 to v0.5 Migration

Stage 1 migrates from legacy `%APPDATA%/ACBH/config.yaml` when `config.json` is missing. The old file was named YAML but parsed as JSON.

Migration copies identity, Coordinator URL, server directory, and backup profile into `config.json`.

Legacy inputs are copied into `legacy/*.bak-<timestamp>`, and a `migration-report.json` is written.

If remote-public config points to localhost, migration/config validation fails instead of silently selecting `127.0.0.1:6121`.

## Phase 2.5 schemaVersion 2

Phase 2.5 migrates user-visible identity from group/member/host wording to a single-owner private instance model.

Mapping:

- old `identity.groupId` -> `compat.legacyGroupId`
- old `identity.memberId` -> `compat.legacyMemberId`
- old `identity.hostId` -> `compat.legacyHostId` and default `device.deviceId`
- old `identity.hostToken` -> `instance.ownerToken` and `compat.legacyHostToken`
- old `identity.deviceName` -> `device.displayName`
- old `server.dir` -> `server.dir`

The migration must not reset `legacyGroupId` or `legacyHostToken`; existing Coordinator v2 data remains reachable through legacy group routes. Existing `config.json` files are copied to `legacy/config.<timestamp>.json` before being rewritten as schemaVersion 2. `migration-report.json` records the source file and backup path.
