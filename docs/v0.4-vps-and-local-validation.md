# ACBH v0.4 Hobby Edition deployment and validation

This guide covers the relay-first scope only: one long-lived local Agent, one
FRP player data plane, a Coordinator control plane, and the loopback web UI.
Archive synchronization and automatic host election are intentionally out of
scope.

## Trust boundary and ports

| Listener | Default | Exposure |
| --- | ---: | --- |
| Coordinator HTTP | `6121/tcp` | VPS; protect with TLS/reverse proxy in production |
| `frps` bind port | `7000/tcp` | VPS, reachable by the Agent |
| Public Minecraft | `25565/tcp` | VPS, reachable by players |
| Agent UI/API | `127.0.0.1:6130` | loopback only; never expose as `0.0.0.0` |
| Local Minecraft | `127.0.0.1:25565` | local FRP target |

Use the same strong random access token for Coordinator heartbeat
authentication and FRP authentication. Hobby Edition stores this token
locally as plaintext, so restrict access to the Agent configuration directory.
The token is redacted from API responses, diagnostics, events, and logs.

## VPS setup

Install a compatible `frps` binary and create a minimal `frps.toml`:

```toml
bindPort = 7000

auth.method = "token"
auth.token = "REPLACE_WITH_A_LONG_RANDOM_TOKEN"
```

Start `frps` using the service manager for the VPS operating system. Allow
inbound TCP ports `7000` and `25565` in both the cloud security group and host
firewall. Do not run another service on the configured public Minecraft port.

Build and start the Coordinator:

```powershell
pnpm install --frozen-lockfile
pnpm --filter @acbh/coordinator build
$env:ACBH_ACCESS_TOKEN = "REPLACE_WITH_A_LONG_RANDOM_TOKEN"
$env:ACBH_FRP_SERVER_PORT = "7000"
$env:ACBH_PUBLIC_MINECRAFT_PORT = "25565"
$env:HOST = "0.0.0.0"
$env:PORT = "6121"
pnpm --filter @acbh/coordinator start
```

The equivalent Linux environment variables may be supplied by a systemd unit.
Before connecting an Agent, verify that `GET /v1/info` reports protocol `1`,
FRP port `7000`, and public Minecraft port `25565`.

## Local Agent setup

Requirements:

- a Java runtime compatible with the selected Minecraft server;
- an imported server directory containing the server JAR and an accepted
  `eula.txt`;
- a compatible `frpc` executable;
- network access to VPS ports `6121`, `7000`, and the public probe endpoint.

Build and run the Agent from the repository root:

```powershell
go build -o acbh-agent.exe ./agent/cmd/acbh-agent
.\acbh-agent.exe hobby serve --address 127.0.0.1:6130 --frpc C:\path\to\frpc.exe `
  --minecraft-auto-restart=true --minecraft-max-restarts=3
```

Open `http://127.0.0.1:6130`, enter only the Coordinator host, port, and access
token, then import the Minecraft server directory. Starting is asynchronous:
Minecraft must become ready before the Agent starts `frpc`. Closing the browser
does not stop either process.

For continuous operation, run the Agent under Windows Task Scheduler or a
Windows service wrapper with restart-on-failure enabled. On Linux, use systemd
with `Restart=on-failure`. Run only one Agent service for a given local server
directory. The Agent persists the desired hosting state and safely rebuilds the
managed processes after an Agent restart.

## Automated verification

Run from the repository root:

```powershell
gofmt -w agent
Push-Location agent
go test ./...
go vet ./...
Pop-Location
pnpm --filter @acbh/coordinator build
pnpm --filter @acbh/coordinator test
```

`gofmt -w agent` is illustrative for a clean checkout; do not use it over
unrelated user edits. CI or maintainers should format only files in the change.

## Manual acceptance matrix

Record timestamps, Agent diagnostics, the last 500 state transitions, and the
rotated JSONL logs for each scenario.

1. **External connection:** start hosting and connect a Minecraft client to
   `VPS:25565`. Confirm the UI reports online only after the local server,
   `frpc` connection, local probe, and public probe are all healthy.
2. **Browser independence:** close every browser window for at least ten
   minutes. Confirm the player remains connected and both Minecraft and `frpc`
   continue running.
3. **Coordinator restart:** restart only the Coordinator. Confirm the player
   session and FRP tunnel remain available while control-plane status becomes
   degraded, then returns online after heartbeat recovery.
4. **`frpc` crash:** terminate the managed `frpc` process. Confirm there is no
   duplicate process and the Agent retries with bounded backoff until the public
   probe succeeds again.
5. **Temporary network loss:** block VPS reachability, then restore it. Confirm
   retry delays are bounded at 30 seconds and state changes from reconnecting to
   online without restarting Minecraft.
6. **Bad token:** configure an invalid token. Confirm authentication is a
   terminal error and the Agent does not produce an infinite retry storm.
7. **Port conflict:** occupy the public Minecraft port. Confirm the failure is
   terminal until configuration or VPS state changes.
8. **Minecraft crash:** terminate Minecraft. Confirm Relay is invalidated and
   the managed `frpc` process is stopped rather than advertising a dead target.
   With the default policy, confirm Minecraft and then Relay recover at most
   three times; after the limit, confirm state remains `ERROR` without a storm.
9. **Agent restart:** restart the Agent while desired hosting state is true.
   Confirm it reconstructs component ownership without starting duplicates.
10. **Graceful stop:** press stop once and repeatedly. Confirm stop is
    idempotent, `frpc` stops before Minecraft, and desired state remains off
    after restarting the Agent.
11. **24-hour soak:** monitor reachability, process count, handle count, memory,
    CPU, and state transitions for 24 hours with periodic player connections.
12. **Seven-day soak:** repeat for seven days with planned Coordinator restart,
    network interruption, and `frpc` crash windows. Confirm logs remain bounded
    to five files of at most 20 MiB each and contain no complete token.

The stop orchestration deliberately leaves the future safe archive-sync hook
after Minecraft has stopped and before the operation completes. Do not add
archive upload/download or automatic host election to this release.

## Legacy isolation check

Before release, inspect the Agent entry path and dependency tree. It must not
import the old WebSocket player relay, Desktop runtime state writers,
`remote-public` state machine, session/lease/tunnel state, or current-host
election. `frpc`/`frps` is the only v0.4 player data plane; Coordinator HTTP is
control-plane traffic only.

The real VPS firewall, Windows service wrapper, external Minecraft client, and
24-hour/seven-day soak are environment-dependent manual checks. A passing unit
test suite does not claim those checks have been performed.
